# Validate

## Идея решения

Моделируем единственный возможный полезный порядок действий. Берём элементы из
`pushed` слева направо и кладём их во вспомогательный стек. После каждого
добавления проверяем: если вершина равна следующему требуемому элементу
`popped`, его нужно и можно сразу снять. Снимаем столько совпадающих вершин,
сколько возможно.

Если после обработки всего `pushed` обработаны все элементы `popped`, такая
последовательность операций существует. Иначе нужный элемент оказался под
другим элементом стека, следовательно получить его нельзя.

## Пошаговая визуализация

Пример: `pushed = [1, 2, 3, 4, 5]`, `popped = [1, 3, 5, 4, 2]`.
`i` — индекс следующего ожидаемого значения в `popped`.

| Действие | Стек, низ → вершина | Следующий `popped[i]` | Снято |
| --- | --- | --- | --- |
| начало | `[]` | `1` | — |
| `push(1)`, вершина совпала | `[]` | `3` | `pop(1)` |
| `push(2)` | `[2]` | `3` | — |
| `push(3)`, вершина совпала | `[2]` | `5` | `pop(3)` |
| `push(4)` | `[2, 4]` | `5` | — |
| `push(5)`, вершина совпала | `[2, 4]` | `4` | `pop(5)` |
| следующая вершина тоже совпала | `[2]` | `2` | `pop(4)` |
| следующая вершина тоже совпала | `[]` | нет | `pop(2)` |

Все значения `popped` сняты, поэтому ответ `True`.

Контрпример: при `pushed = [1, 2, 3]` и `popped = [3, 1, 2]` после
`push(1), push(2), push(3), pop(3)` стек равен `[1, 2]`. Нужно снять `1`,
но вершина — `2`; ответ `False`.

## Сложность

Время — **O(n)**: каждый элемент добавляется в стек и удаляется из него не
более одного раза. Память — **O(n)** в худшем случае, когда до первого
извлечения в стеке находятся все `n` элементов.

`test_validate.py` содержит оба примера из условия, одиночный элемент,

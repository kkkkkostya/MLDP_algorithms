# Merge lists

## Идея решения

У обоих списков просматриваются текущие первые неперенесённые узлы. Меньший
узел уже не может быть обогнан ни одним следующим узлом своего списка, поэтому
его безопасно присоединить к результату. Затем указатель соответствующего
списка сдвигается. Когда один список закончился, оставшаяся часть другого уже
отсортирована и целиком присоединяется к результату.

Реализованы два варианта:

- `merge_with_dummy` начинает строить результат после временного фиктивного
  узла. Это устраняет специальную обработку первого настоящего узла.
- `merge_without_dummy` сначала выбирает меньший первый узел как `head`, а
  затем работает так же. Фиктивный узел не создаётся.

В обоих случаях узлы исходных списков **переиспользуются**: новые узлы для
результата не создаются (кроме служебного фиктивного узла в первом способе,
который не входит в ответ).

## Пошаговая визуализация

Пример: `list1 = 1a -> 2 -> 4a`, `list2 = 1b -> 3 -> 4b`.
Буквы различают равные по значению, но разные узлы. При равенстве выбирается
узел из `list1`.

| Шаг | Сравниваем | Присоединяем | Результат | Остаток `list1` / `list2` |
| --- | --- | --- | --- | --- |
| 0 | — | — | `[]` | `1a,2,4a` / `1b,3,4b` |
| 1 | `1a <= 1b` | `1a` | `1a` | `2,4a` / `1b,3,4b` |
| 2 | `2 > 1b` | `1b` | `1a -> 1b` | `2,4a` / `3,4b` |
| 3 | `2 <= 3` | `2` | `1a -> 1b -> 2` | `4a` / `3,4b` |
| 4 | `4a > 3` | `3` | `1a -> 1b -> 2 -> 3` | `4a` / `4b` |
| 5 | `4a <= 4b` | `4a` | `1a -> 1b -> 2 -> 3 -> 4a` | пусто / `4b` |
| 6 | `list1` пуст | остаток `4b` | `1a -> 1b -> 2 -> 3 -> 4a -> 4b` | пусто / пусто |

В варианте с фиктивным элементом `tail` в начале указывает на временный
`dummy`, а возвращается `dummy.next`, то есть `1a`. В варианте без него на
первом шаге `1a` сразу становится `head` и `tail` результата. Дальнейшие шаги
совпадают.

## Сложность

Пусть в списках `m` и `n` узлов. Время — **O(m + n)**: каждый узел
сравнивается/присоединяется не более одного раза. Дополнительная память —
**O(1)**: используются только несколько указателей; сам результат состоит из
уже существующих узлов.

## Тесты

`test_merge_lists.py` запускает оба варианта на примере из условия, пустых
списках, списках с повторами и отрицательными значениями. Отдельный тест
проверяет по идентичности объектов, что все узлы результата — именно узлы
двух исходных списков.

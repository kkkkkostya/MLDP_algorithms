# Stack vs Queue

## Идея решения

И стек, и очередь хранят элементы в односвязном списке, где каждый узел знает
следующий узел.

- В **стеке** указатель хранится только на вершину. `push` ставит новый узел
  перед прежней вершиной, а `pop` снимает вершину. Поэтому получается LIFO:
  последним пришёл — первым вышел.
- В **очереди** есть два указателя: на начало (`head`) и на конец (`tail`).
  `enqueue` присоединяет узел к `tail`, `dequeue` снимает узел с `head`.
  Поэтому получается FIFO: первым пришёл — первым вышел.


## Пошаговая визуализация

Стек: после `push(10)`, `push(20)`, `push(30)`, `pop()`:

| Операция | Список от вершины к низу | Результат |
| --- | --- | --- |
| начало | `top -> None` | — |
| `push(10)` | `top -> 10 -> None` | — |
| `push(20)` | `top -> 20 -> 10 -> None` | — |
| `push(30)` | `top -> 30 -> 20 -> 10 -> None` | — |
| `pop()` | `top -> 20 -> 10 -> None` | `30` |

Очередь: после `enqueue(10)`, `enqueue(20)`, `enqueue(30)`, `dequeue()`:

| Операция | Список | Результат |
| --- | --- | --- |
| начало | `head, tail -> None` | — |
| `enqueue(10)` | `head, tail -> 10 -> None` | — |
| `enqueue(20)` | `head -> 10 -> 20 <- tail` | — |
| `enqueue(30)` | `head -> 10 -> 20 -> 30 <- tail` | — |
| `dequeue()` | `head -> 20 -> 30 <- tail` | `10` |

Когда из очереди удаляется последний узел, оба указателя становятся `None`.
Это позволяет затем снова безопасно добавлять элементы.

## Сложность

Все `push`, `pop`, `peek`, `enqueue`, `dequeue` выполняются за **O(1)**:
изменяются лишь несколько ссылок. `len()` и `is_empty()` тоже **O(1)**.

Память — **O(n)**, где `n` — количество сохранённых элементов: один узел на
элемент. Дополнительная память одной операции — **O(1)**.

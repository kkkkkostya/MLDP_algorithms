# Задача 2. Permutations

## Решение и идея алгоритма

Функция `permutations(nums, *, trace=True)` из [solution.py](solution.py)
возвращает список уникальных перестановок массива целых чисел. Входной список
остаётся прежним. Для пустого массива результат — `[[]]`: существует одна
перестановка длины 0. Для повторяющихся значений одинаковые перестановки
не дублируются.

```python
from homework_5.permutations.solution import permutations

assert permutations([0, 1]) == [[0, 1], [1, 0]]  # также печатает стек
assert permutations([1], trace=False) == [[1]]
assert permutations([1, 1, 2], trace=False) == [
    [1, 1, 2], [1, 2, 1], [2, 1, 1],
]
```

Используется поиск с возвратом. `Counter` хранит оставшееся количество каждого
значения, а `path` — текущий префикс перестановки.

1. Если длина `path` достигла длины массива, сохранить его копию в результат.
2. Иначе перебрать значения в порядке первого появления во входе.
3. Для доступного значения уменьшить счётчик, добавить его в `path` и вызвать
   `backtrack(path)` рекурсивно.
4. После возврата удалить последний элемент и восстановить счётчик.

Для разных значений порядок ответа совпадает с примерами условия. Словарь
счётчиков не меняет набор ключей во время перебора, меняются только их значения.

В каждом вызове частоты в `path` и оставшиеся частоты в сумме равны частотам
исходного массива. Значение выбирается только при положительном остатке,
поэтому каждый лист содержит все исходные элементы в правильном количестве.
Любая допустимая перестановка задаёт последовательность таких выборов, поэтому
обязательно будет построена. На одном уровне каждое значение рассматривается
один раз, поэтому одинаковых результатов нет. Откат полностью восстанавливает
состояние перед следующей ветвью. Копирование `path` в листе защищает уже
найденные перестановки от последующих изменений.

## Визуализация дерева и стека вызовов

Рекурсивная функция оборачивается в декоратор из
[первой задачи](../tracer/solution.py). Трассировка включена по умолчанию;
`trace=False` отключает только вывод, сохраняя тот же алгоритм и результат.
Входы показывают текущий префикс, а возвраты имеют результат `None`, поскольку
`backtrack` сохраняет перестановки в общем списке `result`.

Дерево выбора для `[1, 2, 3]`:

```text
[]
├── [1]
│   ├── [1, 2] → [1, 2, 3]  №1
│   └── [1, 3] → [1, 3, 2]  №2
├── [2]
│   ├── [2, 1] → [2, 1, 3]  №3
│   └── [2, 3] → [2, 3, 1]  №4
└── [3]
    ├── [3, 1] → [3, 1, 2]  №5
    └── [3, 2] → [3, 2, 1]  №6
```

Пошаговое прохождение первой ветви и переход ко второй:

| Шаг | `path` | Остатки (1, 2, 3) | Действие |
| --- | --- | --- | --- |
| 1 | `[]` | (1, 1, 1) | выбрать 1 |
| 2 | `[1]` | (0, 1, 1) | выбрать 2 |
| 3 | `[1, 2]` | (0, 0, 1) | выбрать 3 |
| 4 | `[1, 2, 3]` | (0, 0, 0) | сохранить копию №1, возврат |
| 5 | `[1, 2]` | (0, 0, 1) | откатить 3; вариантов больше нет, возврат |
| 6 | `[1]` | (0, 1, 1) | откатить 2; выбрать 3 |
| 7 | `[1, 3]` | (0, 1, 0) | выбрать 2 |
| 8 | `[1, 3, 2]` | (0, 0, 0) | сохранить копию №2, возврат |
| 9 | `[]` | (1, 1, 1) | после отката всей ветви выбрать следующий префикс `[2]` |

Полный небольшой пример вывода для `[0, 1]`:

```text
-> backtrack([])
  -> backtrack([0])
    -> backtrack([0, 1])
    <- backtrack = None
  <- backtrack = None
  -> backtrack([1])
    -> backtrack([1, 0])
    <- backtrack = None
  <- backtrack = None
<- backtrack = None
```

Полученный результат: `[[0, 1], [1, 0]]`. Для полного примера `[1, 2, 3]`
запустить из корня: `python -m homework_5.permutations.solution`.

## Сложность

Для n различных элементов время — **O(n · n!)**: дерево поиска содержит
O(n!) вызовов, каждый внутренний вызов перебирает n ключей, а в каждом
из n! листьев копируется список длины n. Память результата — **O(n · n!)**;
дополнительная память без результата и без трассировки — **O(n)** для
счётчиков, текущего пути и рекурсивного стека. Для n = 0 время и память O(1).

При повторениях число результатов равно `n! / (c₁! · c₂! · …)`, где cᵢ —
частоты значений. Предел O(n · n!) остаётся верным, но фактический поиск короче.
Например, для одинаковых элементов он строит единственную цепочку.

Трассировка добавляет стоимость форматирования и печати всех вызовов. При
условно постоянной длине записи одного числа суммарный вывод для различных
элементов также ограничен O(n · n!), но сильно увеличивает практическое время.
Сохранённые в активных обёртках строки аргументов и отступов требуют до
**O(n²)** дополнительной памяти. Эти строки не входят в O(n) для варианта
`trace=False`. Как и любой рекурсивный поиск, реализация ограничена глубиной
рекурсии Python; для больших n сам размер ответа уже факториален.

## Тесты

[test_permutations.py](test_permutations.py) проверяет все примеры условия,
пустой массив, отрицательные числа и ноль, одинаковые значения, отсутствие
дубликатов, неизменность входа и независимость списков результата. Для длин
0–7 ответ сравнивается с `itertools.permutations`, проверяется количество n!.
Для массивов с повторениями ответ сравнивается с множеством перестановок
стандартной библиотеки. Отдельно проверяются точный текст стека, вывод по
умолчанию и совпадение результатов при включённой и отключённой трассировке.

Запуск из корня: `python -m pytest homework_5/permutations -q`.

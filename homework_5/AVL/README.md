# Задача 3. AVL

## Решение и интерфейс

Класс `AVL` из [solution.py](solution.py) реализует дерево поиска целых чисел,
в котором для каждого узла высоты детей отличаются не более чем на 1.
`AVLNode` хранит значение, ссылки на детей и высоту. Высота пустого поддерева
равна 0, листа — 1. Баланс узла: `b = height(left) - height(right)`.

| Метод | Результат |
| --- | --- |
| `AVL(values=())` | создаёт дерево последовательными вставками |
| `insert(value)` | добавляет значение; возвращает `None` |
| `delete(value)` | удаляет значение; возвращает `True`, если оно было, иначе `False` |
| `search(value)` | возвращает `True` или `False` |
| `inorder()` | возвращает список значений по возрастанию |
| `visualize()` | возвращает текстовую схему со сторонами детей, высотами и балансами |

Дерево строгое: слева все значения меньше, справа — больше. Повторные вставки
игнорируются, удаление отсутствующего значения ничего не меняет.

```python
from homework_5.AVL.solution import AVL

tree = AVL([30, 10, 20, 40, 50])
assert tree.search(30) is True
assert tree.search(99) is False
assert tree.delete(10) is True
assert tree.inorder() == [20, 30, 40, 50]
print(tree.visualize())
```

## Идея алгоритмов

**Поиск** совпадает с поиском в BST: сравнить ключ с текущим значением и перейти
к соответствующему ребёнку. Равенство означает успех, пустая ссылка — отсутствие.

**Вставка** рекурсивно находит свободную позицию по правилу BST и создаёт лист.
При возврате из рекурсии для каждого предка пересчитывается высота и, если
нужно, выполняются повороты. Корень поддерева после поворота возвращается
вызывающему и записывается в соответствующую ссылку, включая `self.root`.

**Удаление** сначала проверяет наличие ключа поиском, затем удаляет его как в BST:

- лист заменяется пустой ссылкой;
- узел с одним ребёнком заменяется этим ребёнком;
- узел с двумя детьми получает значение минимального узла правого поддерева
  (следующего по возрастанию), после чего этот преемник удаляется справа.

При возврате на **каждом** уровне вызывается `_rebalance`: при удалении
восстановление баланса может понадобиться у нескольких предков.

**Балансировка.** Сначала `_update` обновляет высоту по высотам детей.
Затем выбирается один из четырёх случаев:

| Условие | Случай | Действия |
| --- | --- | --- |
| `b > 1`, баланс левого ребёнка ≥ 0 | LL | правый поворот |
| `b > 1`, баланс левого ребёнка < 0 | LR | левый поворот ребёнка, правый поворот узла |
| `b < -1`, баланс правого ребёнка ≤ 0 | RR | левый поворот |
| `b < -1`, баланс правого ребёнка > 0 | RL | правый поворот ребёнка, левый поворот узла |

Нулевой баланс ребёнка особенно важен при удалении: он требует одиночного
поворота. Правый поворот сохраняет порядок значений в таком виде:

```text
        y                      x
       / \                    / \
      x   C    →             A   y
     / \                        / \
    A   B                      B   C

    A < x < B < y < C
```

Здесь A, B, C — поддеревья; неравенства относятся ко всем их значениям.
Левый поворот симметричен. После поворота сначала обновляется высота бывшего
корня, затем нового корня, поскольку новый корень зависит от высоты бывшего.

Поиск следует единственному пути, на котором может находиться ключ согласно
свойству BST. Обычная вставка и удаление с заменой на преемника сохраняют
отсортированный inorder. Повороты сохраняют тот же inorder, значит, сохраняют
BST. После изменения поддеревья уже сбалансированы на нижних уровнях; анализ
разницы их высот выбирает поворот, который восстанавливает баланс текущего
узла. Пересчёт высот поддерживает их соответствие реальной структуре дерева.
Возвращаясь до корня, получаем BST с верными высотами и балансом в каждом узле.

## Пошаговая визуализация

Из корня репозитория: `python -m homework_5.AVL.solution`. Программа печатает
дерево после каждой вставки и удаления из следующего примера.

### Вставки и повороты

Вставим по порядку `[30, 10, 20, 40, 50]`.

После вставок 30 и 10:

```text
  30 (h=2, b=1)
 /
10 (h=1, b=0)
```

Вставка 20 даёт левую-правую конфигурацию. Промежуточные состояния поворотов:

```text
    30               30                  20
   /                /                   /  \
  10       →       20         →        10  30
    \             /
    20           10

 b(30)=2      левый поворот 10     правый поворот 30
 b(10)=-1
```

После вставки 40 баланс везде допустим:

```text
    20
   /  \
  10  30
        \
        40
```

Вставка 50 нарушает баланс узла 30; это случай RR:

```text
    20                  20
   /  \                /  \
  10  30       →      10  40
        \                / \
        40              30 50
          \
          50

 b(30)=-2       левый поворот узла 30
```

Итоговое дерево имеет высоту 3, у корня 20 баланс −1.
Для полноты четыре минимальных примера вставок:

| Вставки | Случай | Итоговый корень и дети |
| --- | --- | --- |
| 30, 20, 10 | LL | корень 20, дети 10 и 30 |
| 10, 20, 30 | RR | корень 20, дети 10 и 30 |
| 30, 10, 20 | LR | корень 20, дети 10 и 30 |
| 10, 30, 20 | RL | корень 20, дети 10 и 30 |

### Удаление и поиск

Удалим лист 10 из полученного дерева. У корня 20 слева высота 0, справа 2,
баланс −2; баланс правого ребёнка 40 равен 0. Нужен один левый поворот:

```text
    20                     40
      \                   /  \
      40        →        20  50
     /  \                  \
    30  50                 30
```

Точный результат `visualize()` после удаления:

```text
40 (h=3, b=1)
  L: 20 (h=2, b=-1)
    R: 30 (h=1, b=0)
  R: 50 (h=1, b=0)
```

Поиск 30 проходит шаги `40 → 20 → 30`: меньше 40 — влево, больше 20 — вправо,
равенство — `True`. Поиск 25 проходит `40 → 20 → 30 → None` и возвращает `False`.

Отдельный пример удаления узла с двумя детьми: `AVL([20, 10, 40, 5, 15, 30, 50, 35])`.
Удалим корень 20. Минимум справа — 30, у этого преемника есть правый ребёнок 35:

```text
        20                       30
      /    \                   /    \
    10      40       →       10      40
   /  \    /  \             /  \    /  \
  5   15  30  50           5   15  35  50
            \
            35
```

Шаги: найти 20, скопировать значение 30 в корень, удалить прежний узел 30,
заменив его ребёнком 35, затем пересчитать высоты 40 и нового корня 30.
В этом примере после удаления повороты не нужны.

## Сложность

Пусть n — число узлов. В AVL минимальное число узлов высоты h удовлетворяет
`N(h) = 1 + N(h-1) + N(h-2)`, поэтому растёт экспоненциально с h, а высота
равна O(log n). Сравнения целых и операции над ссылками считаем O(1).

| Операция | Время в худшем случае | Дополнительная память |
| --- | --- | --- |
| `search` | O(log(n + 1)) | O(1) |
| `insert` | O(log(n + 1)) | O(log(n + 1)) для рекурсии |
| `delete` | O(log(n + 1)) | O(log(n + 1)) для рекурсии |
| построение из m значений | O(m log(m + 1)) | O(n) для дерева и O(log(n + 1)) для рекурсии |
| `inorder` | O(n) | O(n) для результата, O(log(n + 1)) для рекурсии |
| `visualize` | O(n log(n + 1)) | O(n log(n + 1)) для текста |

Логарифмические оценки для операций на пустом дереве понимаются как O(1).
На каждом уровне вставки и удаления выполняется O(1) работы: пересчёт высоты
и не более двух поворотов. Дополнительный поиск перед удалением и поиск
преемника не меняют асимптотику. Один поворот требует O(1) времени и памяти.
Всё дерево занимает O(n) памяти. Для визуализации учитывается длина отступов
у каждого узла; длину записи одного значения считаем постоянной.

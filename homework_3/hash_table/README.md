# Собственная хеш-таблица

## Устройство и идея решения

`HashTable` хранит данные только в `list`, как требуется в задании:

```text
таблица (list)
  ├── корзина 0 (list записей)
  ├── корзина 1 (list записей)
  └── ...

запись (list): [ключ, значение]
```

Индекс корзины вычисляется так: `hash(key) % количество_корзин`. Несколько
разных ключей могут получить одинаковый индекс — это коллизия. Она разрешается
**цепочками**: все такие записи лежат в одном списке-корзине, а поиск проходит
только по нему и сравнивает ключи через `==`.

Поддерживаются операции:

- `set(key, value)` — вставляет новую пару или обновляет существующую;
- `get(key, default=None)` — ищет значение, возвращая `default`, если ключа нет;
- `remove(key)` — удаляет ключ и сообщает, было ли удаление успешным;
- `contains(key)` и `len(table)` — дополнительные операции для безопасной
  проверки наличия и размера.

Когда следующая вставка превысит коэффициент заполнения `0.75`, таблица
увеличивается в два раза. Все записи перераскладываются: при новом числе
корзин их индекс может измениться. Благодаря этому цепочки обычно остаются
короткими и основные операции работают быстро.

## Пошаговая визуализация

Для наглядности пусть у таблицы четыре корзины, а ключи `A`, `B`, `C` имеют
следующие хеши: `hash(A)=5`, `hash(B)=1`, `hash(C)=5`.

| Шаг | Операция и индекс | Корзины после операции |
| --- | --- | --- |
| 0 | начало | `0: []`, `1: []`, `2: []`, `3: []` |
| 1 | `set(A, 10)`, `5 % 4 = 1` | `1: [[A, 10]]` |
| 2 | `set(B, 20)`, `1 % 4 = 1` | `1: [[A, 10], [B, 20]]` |
| 3 | `get(B)`: пройти цепочку `A`, затем `B` | найдено `20` |
| 4 | `set(C, 30)`, `5 % 4 = 1` | `1: [[A, 10], [B, 20], [C, 30]]` |
| 5 | `remove(B)`: удалить запись с индексом 1 в цепочке | `1: [[A, 10], [C, 30]]` |

На шагах 1, 2 и 4 случается коллизия: разные ключи остаются доступными, потому
что не затирают друг друга, а добавляются в одну цепочку.

Пример расширения: при 8 корзинах после шестой записи загрузка равна `6 / 8 =
0.75`. Перед седьмой записью она стала бы `7 / 8 = 0.875`, поэтому создаются
16 корзин и все шесть старых записей заново помещаются по формуле
`hash(key) % 16`. Затем добавляется седьмая запись.

## Сложность

При равномерном распределении хешей `set`, `get`, `remove` и `contains`
работают в среднем за **O(1)**. В худшем случае все ключи окажутся в одной
цепочке, тогда каждая из операций займёт **O(n)**.

Расширение занимает **O(n)**, но происходит редко; его амортизированная цена
на одну вставку — **O(1)**. Память — **O(n)** для записей и корзин.
